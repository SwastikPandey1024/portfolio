**Project:** Swastik Pandey — Personal AI Engineering Portfolio

---

# 1. PRODUCT VISION

## Core Thesis

> **I build intelligent systems that turn AI capabilities into useful products across real-world domains.**

The portfolio must communicate that Swastik is not simply someone who experiments with AI models.

The portfolio must demonstrate the ability to:

* identify meaningful problems
* understand domain context
* select appropriate AI approaches
* engineer complete systems
* validate assumptions
* deploy usable products
* communicate technical decisions clearly
* learn from implementation and iteration

## Desired Visitor Reaction

Within the first 15–20 seconds, the visitor should understand:

1. Who Swastik is.
2. What type of systems he builds.
3. What domains he has explored.
4. What evidence proves his capabilities.
5. Where they can explore deeper.

The intended perception is:

> **AI engineer + software builder + product thinker + technically rigorous problem solver.**

The website should feel like a:

**high-end AI systems studio × editorial engineering portfolio × product laboratory**

It must NOT feel like:

* a resume dumped onto a webpage
* a generic developer template
* a badge collection
* a cyberpunk/hacker website
* a flashy WebGL experiment
* a design-only portfolio with weak engineering evidence

# 17. MOTION SYSTEM

Motion must have purpose.

Principle:

> **Fast interaction. Slow atmosphere.**

Micro interaction:
150–250ms

Component transition:
300–500ms

Section reveal:
500–900ms

Ambient visuals:
3–10 seconds

Preferred motion:

* opacity
* translate
* scale
* spring
* clip reveal
* masked image movement
* subtle parallax

Avoid:

* constant floating
* bouncing objects
* excessive rotations
* long blocking animations
* autoplay media
* animation before important content

Framer Motion handles UI motion.

Lenis handles smooth scrolling.

# 20. THREE.JS ENGINEERING RULES

Three.js is allowed because immersion is part of the portfolio concept.

But it must pass:

* desktop smoothness target
* mobile graceful degradation
* no blocking initial render
* reduced-motion fallback
* no layout shift
* proper cleanup of WebGL resources
* lazy loading where possible

If visual complexity harms performance, simplify the scene.

Engineering quality takes priority over visual spectacle.

# 33. PRODUCT PRINCIPLES

The entire portfolio follows:

### 01 — Show, don't claim.

Evidence beats adjectives.

### 02 — Clarity before novelty.

A visitor should always know where they are.

### 03 — Interaction must communicate.

Animation must have meaning.

### 04 — Real work is the visual language.

Use actual systems, screenshots, metrics and architecture.

### 05 — Restraint creates premium perception.

Less decoration, stronger hierarchy.

### 06 — Accessibility is not optional.

Every major interaction needs a fallback.

### 07 — Performance is part of design.

A beautiful slow site is not a successful site.

### 08 — AI assists engineering; it does not replace judgment.

Human decisions remain visible.

### 09 — One visual system, multiple project personalities.

Consistency without repetition.

### 10 — Recruiters should never have to hunt.

Primary evidence must be immediately discoverable.
